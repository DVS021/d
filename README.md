# Стандарты продаж СМБ 1С-Рарус

Локальная версия внутреннего справочного портала на основе предоставленного
`dvis-standards-demo-v02.html`. Без внешних библиотек, шрифтов и запросов к сторонним
сервисам при загрузке. Нужен Node.js 20 или новее; установка пакетов не требуется.

## Запуск

```sh
cd /workspace/d
npm start
```

Открыть в браузере адрес локального сервера с портом 3000. Порт можно изменить
переменной `PORT`. Сервер по умолчанию слушает только локальный интерфейс.
В облаке адрес доступен внутри машины; открытие на компьютере пользователя
потребует отдельного размещения или скачивания автономного файла.

## Проверка и сборка

```sh
npm test
npm run build
```

В `dist/` появятся файлы для статического хостинга и автономный
`dvis-standards.html`, который можно открыть двойным щелчком без Node.js.
Сохранение данных при открытии через `file:` зависит от настроек браузера;
для стабильного сохранения используйте локальный сервер.

## Возможности

- Каталог 18 стандартов, поиск и фильтры; памятки №1–6 с первоисточниками.
- Навигатор рабочих ситуаций с пошаговыми решениями.
- Учебные кейсы и три варианта теста по 20 вопросов с объяснениями ответов.
- Глоссарий и общий поиск (Ctrl/Cmd + K).
- Избранное в каталоге, отметки изучения, чек-листы и сохранение тестовых ответов в браузере.
- Выбор роли для рекомендаций; адаптивное меню и управление с клавиатуры.

## Материалы и ограничения

`assets/data.js` содержит перенесённые из макета материалы и ссылки на документы.
Их актуальность и доступность не подтверждены владельцами. №7–18 не наполнены:
сайт не подменяет их вымышленными правилами. Редактируйте содержание в этом файле,
оформление в `assets/styles.css`, поведение в `assets/app.js`.
Вопросы и ключи трёх вариантов теста находятся в `assets/tests.js`.

Роль — настройка рекомендаций, а не авторизация. Данные прогресса локальные,
на одном браузере и адресе сайта; они не передаются руководителю и не синхронизируются.
Корпоративная авторизация, серверная база прогресса, интеграция с ЕИС и
автосинхронизация документов в эту версию не входят. Для общего внутреннего
использования размещайте сайт за корпоративным входом.

Работайте в существующем checkout: облачная задача уже изолирована, создавать
дополнительный Git worktree для запуска не требуется.


## Публикация через GitHub Pages

Исходники сайта должны находиться в ветке `main` репозитория `DVS021/d`.
В настройках репозитория откройте **Settings → Pages → Build and deployment**,
выберите **Deploy from a branch → main → / (root)** и нажмите **Save**.
Файл `.nojekyll` позволяет публиковать статические файлы без обработки Jekyll.
Дождитесь успешного задания Pages в Actions. Ожидаемый адрес:
`https://dvs021.github.io/d/` — он работает только после включения и завершения публикации.
Для приватного репозитория доступность Pages зависит от тарифа GitHub;
не меняйте видимость репозитория ради публикации без отдельного решения владельца.

Для обновления сайта измените исходники и отправьте коммит в `main`.
GitHub Pages публикует исходный `index.html` и каталог `assets/`, Node.js на сервере не нужен.

## Видеокейсы СМБ «1С-Рарус»

Раздел `#videos` общий для СМБ. Каталог — `assets/videos.js`;
видео, обложки и субтитры хранятся в `media/videos/`. До получения настоящих
роликов библиотека показывает пустое состояние. Тестовые видео не публикуются.

Добавить полученный файл:

```sh
npm run add-video -- /path/to/video.mp4 --id first-contact --title "Первый контакт с клиентом" --description "Разбор разговора и следующего шага" --standards 2,3 --category "Входящие обращения" --duration 125
```

`--duration` — длительность в секундах; необязательные `--poster /path/cover.jpg`
и `--captions /path/captions.vtt` добавляют обложку и русские субтитры.
Для MP4 используйте H.264/AAC для совместимости с браузерами. WebM и OGV
тоже поддерживаются. Перед публикацией проверьте реальное воспроизведение.
Скрипт принимает файлы до 95 MiB, чтобы не превысить лимит одного файла GitHub,
и не перезаписывает существующие ролики. После импорта выполните `npm test`,
`npm run build`, затем включите каталог и media в коммит и отправьте в `main`.
Сборка проверяет наличие файлов и копирует их в опубликованный сайт.

Плеер поддерживает полноэкранный режим, перемотку, просмотр с телефона,
субтитры и открытие исходного файла. Локальный сервер поддерживает HTTP Range.
Для автономного HTML с видео необходимо сохранять рядом каталог `media/`.
Загрузка файла в браузере не публикует его для других сотрудников: новые
материалы добавляются через репозиторий и обычную публикацию GitHub Pages.

Оформление и навигация относятся ко всей СМБ «1С-Рарус». Имена исходных
документов и учебных архивов СМБ сохранены для точного указания происхождения;
смена бренда не меняет нормативный статус материалов.

## Глоссарий, памятки и схемы редакции 2

`#glossary` содержит 87 полных определений из `documents/glossary-v2.docx`.
Доступны поиск по определениям, тематические фильтры и прямые ссылки вида
`#glossary/term-034`. Короткий старый словарь заменён в интерфейсе данными
присланного Стандарта №1 редакции 2 от 18.09.2026.

`#memos` — 8 памяток по стандартам №1–6 из присланной презентации.
`#memo/1` … `#memo/6` открывают полные тексты с выделенными правилами,
рисками и нормативами. Для стандартов №4 и №5 представлены по две памятки.
Исходный PPTX сохранён в `documents/sales-memos-v2.pptx`; читаемый PDF
для печати — `documents/sales-memos-v2.pdf`. PDF свёрстан из того же текста,
а не является факсимильным экспортом презентации.

`#visuals` — интерактивные маршруты обработки обращений, сравнение Лида
и Интереса, условия стадий Интереса и цикл следующего шага. Нормативы
и формулировки взяты из присланных памяток; схемы не являются статистикой продаж.

Содержимое — `assets/learning.js`, представление — `assets/learning-ui.js`.
`npm test` теперь требует Python 3 (только стандартная библиотека) и сверяет
каждое определение и каждый абзац памяток с исходными DOCX/PPTX. Python не
нужен для запуска самого сайта. Не меняйте данные редакции 2 без сверки
с оригиналами. Существующие тесты знаний по редакции 1 не переименованы
в редакцию 2: их предупреждение об исходной версии сохранено.

Печатный PDF можно повторно подготовить в Chromium/Playwright из маршрута
`#memo/print`: формат A4, альбомная ориентация, поля 0, печать фона включена.
Ожидается 8 страниц. После изменения PDF выполните `npm run build`.

Видеокейсы: пользовательская папка Google Drive добавлена в раздел `#videos`
с прямой ссылкой и необязательным встроенным просмотром. Доступ зависит от
настроек Google Drive. Пока исходные ролики не скачаны, они не заявляются
как загруженные на GitHub Pages.

## Встроенный видеоплеер

Раздел `#videos` содержит плеер непосредственно на странице и переключатель
роликов общей подборки. Поддерживаются локальные файлы и Google Drive:

```js
{
  id: 'control-k3',
  title: 'Контроль К3',
  description: 'Разбор рабочего кейса',
  provider: 'google-drive',
  driveId: 'ID_ФАЙЛА_ИЗ_ССЫЛКИ_GOOGLE_DRIVE',
  category: 'Контроль качества',
  standards: [1, 6]
}
```

Значения ID, названия и связи со стандартами добавляйте только по полученным
файлам и их содержимому. Не подставляйте ID папки вместо ID видео. Встроенный
просмотр использует `https://drive.google.com/file/d/ID/preview`; доступ к
самому ролику по-прежнему регулируется Google Drive. Если ссылка содержит
`resourcekey`, сохраните его в поле `resourceKey`. Другие параметры ссылки
в адрес плеера не переносятся.

Форма «Открыть видео по ссылке Google Drive» позволяет посмотреть отдельный
ролик внутри текущей страницы. Она не сохраняет ссылку в общей библиотеке,
не загружает файл на хостинг и не меняет права доступа. Рядом с плеером есть
ссылка для открытия видео отдельно, если встроенный просмотр требует входа.
При выборе другого ролика предыдущий плеер удаляется, чтобы воспроизведения
не накладывались. Автоматического запуска видео нет.

## Автоматическое добавление видео из папки

Папка загрузки: `media/videos/` в репозитории `DVS021/d`.
Положите туда MP4, WebM или OGV с понятным именем, например
`Кейс 2 — Контроль К3.mp4`. При сборке сайт сам добавит файл в библиотеку
и подборку плеера. Русские имена, пробелы и заглавные расширения поддерживаются.
Подпапки не сканируются, файлы не переименовываются.

Каталог генерирует `scripts/video-catalog.mjs`. В режиме `npm start` он
обновляется при загрузке страницы, без перезапуска сервера. При
`npm run build` создаётся итоговый `dist/assets/videos.js`; исходный
`assets/videos.js` сохраняется. Удалённые видео исчезают из каталога и
из новой сборки. Ручные записи по тому же `src` имеют приоритет, чтобы
не терять описания, обложки и связи со стандартами.

Через веб-интерфейс GitHub загружаются файлы до 25 МБ. Для более крупных
файлов используйте GitHub Desktop; GitHub не принимает файлы более 100 МиБ.
Сам плеер не загружает видео в репозиторий: файлы размещает владелец,
сайт подхватывает их после успешной сборки и публикации. Пока изменения
находятся только в черновике, действующий интернет-сайт не получает эту функцию.
