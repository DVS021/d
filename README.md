# Стандарты продаж ГК ДВИС

Локальная версия внутреннего справочного портала на основе предоставленного
`dvis-standards-demo-v02.html`. Без внешних библиотек, шрифтов и запросов к сторонним
сервисам при загрузке. Нужен Node.js 20 или новее; установка пакетов не требуется.

## Запуск

```sh
cd /workspace/d
npm start
```

Открыть в браузере адрес локального сервера с портом 3000. Порт можно изменить
переменной `PORT`. Сервер по умолчанию слушает только локальный интерфейс.
В облаке адрес доступен внутри машины; открытие на компьютере пользователя
потребует отдельного размещения или скачивания автономного файла.

## Проверка и сборка

```sh
npm test
npm run build
```

В `dist/` появятся файлы для статического хостинга и автономный
`dvis-standards.html`, который можно открыть двойным щелчком без Node.js.
Сохранение данных при открытии через `file:` зависит от настроек браузера;
для стабильного сохранения используйте локальный сервер.

## Возможности

- Каталог 18 стандартов, поиск и фильтры; памятки №1–6 с первоисточниками.
- Навигатор рабочих ситуаций с пошаговыми решениями.
- Учебные кейсы и три варианта теста по 20 вопросов с объяснениями ответов.
- Глоссарий и общий поиск (Ctrl/Cmd + K).
- Избранное в каталоге, отметки изучения, чек-листы и сохранение тестовых ответов в браузере.
- Выбор роли для рекомендаций; адаптивное меню и управление с клавиатуры.

## Материалы и ограничения

`assets/data.js` содержит перенесённые из макета материалы и ссылки на документы.
Их актуальность и доступность не подтверждены владельцами. №7–18 не наполнены:
сайт не подменяет их вымышленными правилами. Редактируйте содержание в этом файле,
оформление в `assets/styles.css`, поведение в `assets/app.js`.
Вопросы и ключи трёх вариантов теста находятся в `assets/tests.js`.

Роль — настройка рекомендаций, а не авторизация. Данные прогресса локальные,
на одном браузере и адресе сайта; они не передаются руководителю и не синхронизируются.
Корпоративная авторизация, серверная база прогресса, интеграция с ЕИС и
автосинхронизация документов в эту версию не входят. Для общего внутреннего
использования размещайте сайт за корпоративным входом.

Работайте в существующем checkout: облачная задача уже изолирована, создавать
дополнительный Git worktree для запуска не требуется.


## Публикация через GitHub Pages

Исходники сайта должны находиться в ветке `main` репозитория `DVS021/d`.
В настройках репозитория откройте **Settings → Pages → Build and deployment**,
выберите **Deploy from a branch → main → / (root)** и нажмите **Save**.
Файл `.nojekyll` позволяет публиковать статические файлы без обработки Jekyll.
Дождитесь успешного задания Pages в Actions. Ожидаемый адрес:
`https://dvs021.github.io/d/` — он работает только после включения и завершения публикации.
Для приватного репозитория доступность Pages зависит от тарифа GitHub;
не меняйте видимость репозитория ради публикации без отдельного решения владельца.

Для обновления сайта измените исходники и отправьте коммит в `main`.
GitHub Pages публикует исходный `index.html` и каталог `assets/`, Node.js на сервере не нужен.
